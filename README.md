# Контакт-центр службы доставки

Симуляция работы контакт-центра службы доставки с системой массового обслуживания. Реализация покрывает требования варианта 1: бесконечные источники с пуассоновским потоком, буфер «по кольцу» (Д1ОЗ1), отказ при переполнении (Д1ОО1), выбор заявок FIFO (Д2Б1), приоритет по номеру оператора (Д2П1), календарь событий в пошаговом режиме (ОД1) и автоматический режим с графиками (ОР2).

## Установка зависимостей

```bash
pip3 install -r requirements.txt
```

## Расшифровка варианта

`ИБ ИЗ1 ПЗ2 Д1ОЗ1 Д1ОО1 Д2П1 Д2Б1 ОР2 ОД1`

- **ИБ**: бесконечный источник. Клиенты звонят, поток бесконечный.
- **ИЗ1**: пуассоновский закон генерации заявок. Интенсивность каждого источника задаётся параметром `-l`.
- **ПЗ2**: равномерный закон обслуживания приборами.
- **Д1ОЗ1**: буферная память «по кольцу». Указатели вставки и удаления перемещаются циклически по фиксированным позициям буфера.
- **Д1ОО1**: при переполнении буфера — отказ. Заявка отклоняется событием `reject` с причиной `overflow`.
- **Д2П1**: выбор прибора по приоритету номера — поиск свободного оператора с наименьшим номером.
- **Д2Б1**: FIFO — заявка, дольше всех простоявшая в буфере, выбирается на обслуживание первой.
- **ОД1**: динамика — календарь событий, буфер, текущее состояние (пошаговый режим).
- **ОР2**: итоги — графики загрузки операторов, количества отказов, средней очереди (автоматический режим).

## Запуск

```bash
python3 -m app              # пошаговый режим с дефолтами
python3 -m app auto         # автоматический режим с дефолтами
python3 -m app -h           # справка по всем параметрам
```

### Параметры системы (для экспериментов с загрузкой ρ)

| Флаг | Назначение | По умолчанию |
|------|-----------|-------------|
| `-n` | Количество источников | 2 |
| `-l` | Интенсивность λ на источник | 0.6 |
| `-m` | Количество операторов | 3 |
| `-b` | Размер буфера | 8 |

Пример с другой конфигурацией:

```bash
python3 -m app step -n 4 -l 0.8 -m 2 -b 10 --steps 40
python3 -m app auto -n 3 -l 1.0 -m 4 -b 12 --duration 100
```

### Пошаговый режим (ОД1 — календарь событий)

На каждом шаге выводится таблица: время, события, состояние буфера, операторов, указатели, % отказов.

### Автоматический режим (ОР2 — графики)

Выводятся итоговые метрики и файл `artifacts/auto_mode_metrics.png` с графиками:

1. Длина буфера во времени;
2. Процент отказов во времени;
3. Загрузка операторов (бар-чарт).

## Ответ: когда использовать зонную буферную память?

- **Зонная память** полезна для SLA-ограничений по источникам: когда критично, чтобы ни один источник не «вытеснил» остальные и нужно гарантировать минимальные квоты буфера (например, VIP-клиенты vs массовые). Она помогает ограничить накопление неважных заявок и защитить приоритетный трафик.
- **Общий буфер** предпочтителен при равноправных источниках и динамически меняющейся нагрузке, когда важно использовать весь объём памяти целиком для максимизации пропускной способности.
