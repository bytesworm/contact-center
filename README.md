# Контакт-центр службы доставки

Симуляция работы контакт-центра службы доставки с системой массового обслуживания. Реализация покрывает требования варианта: диспетчер с возможностью прямого маршрута на прибор, пакетная обработка заявок, вариант с зонной буферной памятью, календарь событий в пошаговом режиме и автоматический режим с графиками параметров.

## Установка зависимостей

```bash
pip3 install -r requirements.txt
```

## Расшифровка варианта

- **Бизнес-домен**: контакт-центр службы доставки. Клиенты звонят, поток бесконечный и распределён по закону Пуассона.
- **Источники (ИБ, ИЗ1)**: звонки клиентов. Реализовано произвольное количество источников, интенсивность каждого задаётся параметром `--lambda-rate`.
- **Буфер (Д1031)**: очередь ожидания IVR «по кольцу». Поддерживаются общий и зонный режимы (`--buffer-mode`), указатели отображаются в календаре.
- **Прибор (ПЗ2)**: операторы кол-центра. Время обслуживания равномерно распределено, приборы освобождаются независимо.
- **Дисциплина отказа (Д1001)**: при переполнении буфера заявка сбрасывается событием `reject`.
- **Дисциплины постановки (Д2П1, Д2Б1)**: приоритет обслуживает оператор с наименьшим номером, порядок заявок FIFO. При наличии пакета все приборы обслуживают его целиком, затем формируется новый.
- **Заявка**: звонок клиента на оформление или уточнение заказа.
- **Отображение результатов (ОР2, ОД1)**: динамика — календарь событий (поступление, очередь, отказ, разговор); итоги — графики загрузки операторов, количества отказов, средней очереди и обслуживания.

## Режимы моделирования

### Пошаговый режим (календарь событий)

```bash
python3 -m app --mode step --steps 25 --delta 0.5 --buffer-size 8 --operators 3
```

На каждой итерации выводится таблица:

- время моделирования;
- список событий текущего шага;
- состояние буфера и разбивка по источникам;
- состояние операторов (заняты / свободны, время освобождения, номер заявки);
- положение указателей буфера;
- накопленный % отказов.

### Автоматический режим

```bash
python3 -m app --mode auto --duration 60 --delta 0.25 --graph-dir artifacts --direct-dispatch
```

Выводятся итоговые метрики и путь до файла `auto_mode_metrics.png` с графиками:

1. Длина буфера во времени;
2. Процент отказов во времени;
3. Загрузка операторов (бар-чарт).

## Пакетная обработка

- Как только прибор освобождается и из буфера выбирается заявка, формируется пакет из всех заявок буфера соответствующего источника. Пакет фиксирован и не расширяется новыми заявками, даже если они из того же источника.
- Все операторы обслуживают только текущий пакет (`packet_created` → `packet_select` → `sent_to_operator`). Новый пакет формируется после `packet_completed`.
- В календаре видно, какие заявки входят в пакет, и в каком порядке они выбраны.

## Ответ: когда использовать зонную буферную память?

- **Зонная память** полезна для SLA-ограничений по источникам: когда критично, чтобы ни один источник не «вытеснил» остальные и нужно гарантировать минимальные квоты буфера (например, VIP-клиенты vs массовые). Она помогает ограничить накопление неважных заявок и защитить приоритетный трафик.
- **Общий буфер** предпочтителен при равноправных источниках и динамически меняющейся нагрузке, когда важно использовать весь объём памяти целиком для максимизации пропускной способности.
